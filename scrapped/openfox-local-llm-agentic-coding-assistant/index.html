OpenFox: A Local-LLM-First Agentic Coding Assistant

August 23, 2026 4 min read
#Open Source #Local LLM #AI Coding Agent #vLLM #Ollama

Modern AI coding assistants often lock developers into cloud ecosystems and proprietary subscriptions. OpenFox flips the script by providing a local-LLM-first, autonomous coding agent that comes fully configured straight out of the box.

With contract-driven execution pipelines, native support for popular local inference backends, and multi-turn workflows, OpenFox gives you complete control over your AI-assisted development stack without sacrificing agentic power.

Key Architectural Highlights

OpenFox combines structured planning, rigorous criteria verification, and local execution:

  • Contract-Driven Execution: Uses acceptance criteria as an immutable contract between you and the agent.
  • Plan → Builder Pipeline: Interactive task decomposition followed by autonomous code generation.
  • Iterative Verification: Loops and executes unit tests, builds, and checks until all defined criteria pass.
  • Language Server Protocol (LSP) Support: Built-in LSP communication gives the agent immediate feedback on compile and type errors.
  • Real-Time Performance Metrics: Transparent tracking of prefill time, token generation rate, and total context window utilization.

Quick Start

Getting started with OpenFox requires Node.js (>= 24.0.0) and an OpenAI-compatible local model server running locally (e.g., vLLM, sglang, Ollama, or llama.cpp).

Install the package globally via npm:

npm i -g openfox
openfox

On the initial launch, OpenFox automatically probes and detects active local inference endpoints, configuring the connection parameters without manual intervention.

What’s New in OpenFox 2.0

The 2.0 release brings major performance, stability, and extensibility improvements to the agent lifecycle:

1. Unified Multi-Turn Agent Engine

The agent loop has been redesigned from the ground up using an event-sourced EventStore architecture. All modes—planner, builder, verifier, and sub-agents—execute through the exact same unified loop.

2. Enhanced Provider Configuration

A brand-new Provider Dialog introduces UI-level controls for reasoning effort (reasoningEffort), profile defaults, and provider presets.

3. Configurable Auto-Retry Logic

Replaces rigid XML safeguards with custom regex and pattern-matching triggers that tell the model when to retry tool generation.

4. Cross-Model Vision Fallback

For setups running text-only LLMs alongside vision tasks, OpenFox introduces automatic pre-turn visual descriptions so any model can understand uploaded images.

5. Unified Session Metadata & Sub-Groups

A centralized session_metadata tool enables granular CRUD operations on criteria directly inside the UI. Additionally, workflow sub-groups allow isolating specific phases like automated code review.

6. Concurrency Safety

A per-file mutex locks concurrent edit_file calls, preventing race conditions during parallel file modifications.

CLI Reference

OpenFox includes a dedicated CLI for server management and provider administration.

Common Commands

# Start the OpenFox server in the current workspace
openfox

# Run on a custom port
openfox --port 8080

# Start in headless mode (suppress browser launch)
openfox --no-browser

# Inspect current setup
openfox config

# Provider management
openfox provider add
openfox provider list
openfox provider use
openfox provider remove

CLI Options

Option Description Default
-p, --port <number> Specify web server port 10369
--no-browser Prevent automatic browser launch Opens browser
-h, --help Display help menu —
-v, --version Display installed version —

Extending OpenFox with Plugins

OpenFox supports a plugin system to inject extra authentication providers, transport protocols, and model discovery without touching core code.

Plugin Directories by OS

  • macOS: ~/Library/Application Support/openfox/plugins
  • Linux: ${XDG_CONFIG_HOME:-~/.config}/openfox/plugins
  • Windows: %APPDATA%\openfox\plugins

Supported Provider Plugins

  • openfox-chatgpt: Connect directly using ChatGPT Plus/Pro credentials.
  • openfox-github-copilot: Authenticate using GitHub Copilot.
  • openfox-google-antigravity: Google Cloud and Antigravity endpoint support.
  • openfox-xai-supergrok: xAI Grok provider connector.

Configuration & Environment Variables

You can customize your instance using environment variables:

Variable Default Description
OPENFOX_LLM_URL http://localhost:8000/v1 Base URL for the OpenAI-compatible local LLM endpoint
OPENFOX_BACKEND unknown Active backend engine (vllm, sglang, ollama, llamacpp)
OPENFOX_MAX_CONTEXT 200000 Context window ceiling in tokens
OPENFOX_PORT 10369 OpenFox local web server port
OPENFOX_HOST 127.0.0.1 Local listening host
OPENFOX_REASONING_EFFORT none Extended reasoning depth (none, low, medium, high)
OPENFOX_LOG_LEVEL info Logging verbosity (debug, info, warn, error)
OPENFOX_DB_PATH ./openfox.db Embedded SQLite database location

Conclusion

OpenFox represents a significant step forward for developers seeking a self-hosted, private, and agentic coding assistant. By combining strict contract-driven task verification with support for the latest open-weight models, it unlocks enterprise-grade AI pairing directly on local hardware.
